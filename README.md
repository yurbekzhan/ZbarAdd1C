# ZbarAdd1C

Проект внешней нативной компоненты C++ для **1С, Windows x64**.
Назначение — распознавание QR-кодов в PNG через
[mchehab/zbar](https://github.com/mchehab/zbar).

## Текущее состояние

Реализованы ядро `qr_core`, компонент `ZbarAdd1C` (Native API) и утилита
`qr_scan`. Использованы заголовки из предоставленного пользователем примера
`1CGetImageFragment` и предоставленная методология. Исходные заголовки сохранены
без изменений в `third_party/1c/include`. Современные функции согласования
возможностей реализованы отдельно, поскольку их нет в старых заголовках.

Сборка и тесты выполнены на Linux x64, включая динамическую загрузку библиотеки
и вызовы через `IComponentBase`. **Windows DLL и загрузка в реальной 1С пока
не проверены**: среда разработки Linux, Windows и платформа 1С здесь отсутствуют.

- [Методология Native API](https://its.1c.ru/db/metod8dev#content:3221:hdoc:properties)
- [Шаблон компоненты](https://its.1c.ru/db/files/1CITS/EXE/DOC_10_2/DOC_10_2.zip)

Ядро читает PNG по пути, возвращает все найденные QR-коды. Другие штрихкоды
отключены. Отсутствие QR возвращает пустой список; ошибки чтения, повреждённый
PNG и превышение лимитов вызывают `std::runtime_error`.
Поддерживаются RGB, grayscale, палитра и прозрачность (композиция на белом фоне).
Лимиты: 64 МиБ входного файла и 32 мегапикселя. Строки содержат байты,
возвращённые ZBar; порядок нескольких результатов не гарантируется.

## Интерфейс 1С

Имя класса — `ZbarQR`, имя расширения — `ZbarQR`.
Для идентификатора подключения `Zbar` объект создаётся как `AddIn.Zbar.ZbarQR`.

| Английский метод | Русский метод | Результат |
| --- | --- | --- |
| `Version()` | `Версия()` | Строка `0.1.0` |
| `ReadQR(ПутьPNG)` | `ПрочитатьQR(ПутьPNG)` | Первый QR; пустая строка, если QR нет |
| `ReadQRs(ПутьPNG)` | `ПрочитатьВсеQR(ПутьPNG)` | JSON-массив строк; `[]`, если QR нет |

Путь — непустая строка UTF-16. Результаты ZBar преобразуются из UTF-8 в UTF-16;
произвольные двоичные QR с некорректным UTF-8 не поддерживаются этими строковыми
методами. Ошибка передаётся через `AddError`, а вызов возвращает `false`.
Возвращаемые буферы выделяются только через `IMemoryManager::AllocMemory`;
освобождает их платформа. Свойств и параметров по умолчанию нет.
Методы предназначены для вызова как функции.

Пример подключения и чтения JSON: [examples/read_qr.bsl](examples/read_qr.bsl).
На сервере путь PNG относится к файловой системе сервера. Библиотека экспортирует
`GetClassNames`, `GetClassObject`, `DestroyObject`, `SetPlatformCapabilities` и
`GetAttachType`; допускает изолированное и неизолированное подключение.

## Сборка

Нужны CMake >= 3.20, компилятор C++17, ZBar с QR-декодером, libpng с
simplified read API и zlib. Зависимости должны соответствовать архитектуре
и выбранному компилятору. Сборка ядра и тесты проверены на Linux x64
(GCC 14, ZBar 0.23.93, libpng 1.6.48). На Linux также нужны заголовки `uuid-dev`
для заголовков Native API из примера.

### Windows x64

Вариант для проверки ядра: MSYS2 **UCRT64**, в его терминале:

```sh
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja mingw-w64-ucrt-x86_64-zbar mingw-w64-ucrt-x86_64-libpng
cmake -S . -B build-win -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build-win
ctest --test-dir build-win --output-on-failure
./build-win/qr_scan.exe tests/fixtures/qr.png
```

Этот Windows-сценарий пока не выполнялся. Для MSVC нужны совместимые сборки
ZBar/libpng/zlib; укажите их префикс через `-DCMAKE_PREFIX_PATH=...`.
Нельзя смешивать библиотеки MSVC и MinGW. MSVC-сборка использует статический CRT
(`/MT`, `/MTd`); зависимости для MSVC должны использовать совместимый CRT.
Windows-сборка включает манифест DLL и отвергает 32-битную конфигурацию.
Результат сборки — `build-win/ZbarAdd1C.dll` (для многоконфигурационного генератора
смотрите подкаталог `Release`).

MSYS2-сценарий использует динамические зависимости: их DLL должны быть доступны
загрузчику и платформе 1С. Он предназначен для разработки, комплект поставки
ещё не подготовлен. Согласно методологии, для поставки требуется статически
включить допустимые по лицензии несистемные runtime-библиотеки; для ZBar нужно
отдельно соблюсти LGPL. Не переносите в поставку DLL из старого x86-примера.

### Linux (проверка ядра)

```sh
sudo apt-get install build-essential cmake libzbar-dev libpng-dev uuid-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 2
ctest --test-dir build --output-on-failure
./build/qr_scan tests/fixtures/qr.png
```

`qr_scan` принимает один путь и печатает каждый результат с новой строки
(это диагностический вывод, не формат сериализации). Код завершения: `0` — QR
найден, `2` — QR нет, `1` — ошибка. На Windows путь принимается через `wmain`,
чтобы поддерживать имена файлов Unicode.

## Проверки

CTest запускает два набора. `qr_reader` проверяет 10 функциональных случаев: обычный,
палитровый, прозрачный и повёрнутый PNG; два QR; пустое изображение; кириллица
в QR; отсутствующий, повреждённый и усечённый файл. Фикстуры сохранены в
`tests/fixtures`; Python не требуется для запуска тестов.

`native_api` загружает собранную библиотеку через системный загрузчик,
проверяет экспорт, создание/удаление объекта, английские и русские имена,
менеджер памяти (включая отказ выделения), передачу ошибок, чтение одного/нескольких
QR, Unicode в данных и пути, экранирование JSON. Тестовый хост не заменяет
интеграционную проверку в платформе 1С.

Для пересоздания фикстур используйте отдельное Python-окружение:

```sh
python -m pip install -r tests/requirements.txt
python tests/generate_fixtures.py
```

## Оставшаяся проверка

Собрать DLL на Windows x64, проверить зависимости и встроенный манифест,
подключить в нужной версии платформы 1С и выполнить пример на реальных PNG.
Для целевой версии 1С желательно дополнительно сверить заголовки с её актуальным
SDK: предоставленный пример содержит старый интерфейс локализации `SetLocale`.
Мобильная платформа, веб-клиент и упаковка bundle сейчас не входят в реализацию.

ZBar распространяется по LGPL-2.1-or-later. При подготовке Windows-поставки
нужно включить уведомления и выполнить условия лицензий распространяемых
зависимостей; чужие исходники и бинарные библиотеки в этот репозиторий не включены.
