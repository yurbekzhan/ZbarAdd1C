# ZbarAdd1C

Внешняя компонента **Native API для 1С, Windows x86 и x64**: распознаёт QR-коды в PNG
на основе [mchehab/zbar](https://github.com/mchehab/zbar).

## Сборка в Visual Studio 2022

1. Установите Visual Studio 2022 с нагрузкой **«Разработка классических приложений
   на C++»**. В ней должны быть MSVC v143 x64, Windows SDK и **средства CMake для Windows**.
2. Скачайте ZIP репозитория и распакуйте его. В Visual Studio выберите
   **Файл → Открыть → Папка**, укажите каталог с `CMakeLists.txt`.
3. Выберите конфигурацию **Windows x86 + x64 Release (universal 1C package)**
   (`windows-all-release`) и дождитесь окончания настройки CMake.
4. Нажмите **Сборка → Собрать всё**.

Не нужно отдельно устанавливать ZBar, libpng, zlib, iconv, Git, Python или
менеджер пакетов. Полные исходники зависимостей включены в репозиторий;
проверяются SHA256 и собираются тем же компилятором вместе с проектом.
После установки инструментов Visual Studio сборка не требует Интернета.
Установите инструменты MSVC сразу для x86 и x64 (стандартный компонент x64/x86).
Поддерживается MSVC из установленной Visual Studio: при сборке второй архитектуры
используются та же установка VS и тот же набор инструментов, что и в основной
сборке (без принудительного требования v143). Для новых версий VS нужны
соответствующие актуальные средства CMake.
Основная конфигурация собирает x64, затем автоматически запускает MSBuild для
x86 в отдельном каталоге `secondary-x86-<toolset>`; вручную переключать архитектуру не нужно.
Доступны и отдельные конфигурации `windows-x86-release` и `windows-x64-release`.

Результаты обычной сборки:

```text
out/build/windows-all-release/dist/Release/
    ZbarAdd1C_x86.dll      ← для 32-разрядной 1С
    ZbarAdd1C_x64.dll      ← для 64-разрядной 1С
    Manifest.xml            ← описывает обе архитектуры
    ZbarAdd1C-windows.zip    ← единый пакет для общего макета
    licenses/               ← лицензии зависимостей
    source/                 ← исходники и инструкции для пересборки/перелинковки
```

Несистемные DLL ZBar/libpng/zlib/iconv рядом с компонентой не нужны. MSVC runtime
собирается статически (`/MT` для Release, `/MTd` для Debug). Системные DLL Windows
по-прежнему используются. В DLL включён отдельный Windows assembly manifest;
он не заменяет файл `Manifest.xml` пакета 1С.

Если нужен привычный `.sln`, из **x64 Native Tools Command Prompt for VS 2022**:

```bat
cd /d C:\Projects\ZbarAdd1C
cmake -S . -B build-vs -G "Visual Studio 17 2022" -A x64 -DZBAR1C_DUAL_ARCH=ON
```

Откройте `build-vs/ZbarAdd1C.sln`, выберите **Release / x64**, выполните
**Собрать решение**. DLL и ZIP будут в `build-vs/dist/Release`.
Для командной строки сборка и тестирование (143 в пути — номер toolset; для другой версии используйте созданный каталог `secondary-x86-*`):

```bat
cmake --build build-vs --config Release --parallel 2
ctest --test-dir build-vs -C Release --output-on-failure
ctest --test-dir build-vs/secondary-x86-143 -C Release --output-on-failure
```

В **Обозревателе тестов** Visual Studio также доступны `qr_reader` и `native_api`.
Для диагностики отдельного файла есть `qr_scan.exe <путь.png>`: код завершения
`0` — найден QR, `2` — QR нет, `1` — ошибка. Результаты печатаются с новой строки.

## Использование в 1С

Прямое подключение DLL — [examples/read_qr.bsl](examples/read_qr.bsl).
Для установки из общего макета создайте макет типа **ДвоичныеДанные**, загрузите
`ZbarAdd1C-windows.zip` и используйте `ОбщийМакет.<ИмяМакета>` вместо пути DLL
в вызове `ПодключитьВнешнююКомпоненту`. При необходимости на клиенте сначала
выполните установку внешней компоненты средствами вашей версии платформы.

При подключении ZIP из общего макета 1С выбирает DLL по разрядности своего
процесса. Клиент x86 на Windows x64 использует `ZbarAdd1C_x86.dll`; сервер x64
использует `ZbarAdd1C_x64.dll`. При прямом подключении DLL путь нужно выбрать
самостоятельно. Разрядность ОС сама по себе не определяет разрядность 1С. В серверном вызове PNG должен быть доступен на сервере.

Имя класса и расширения — `ZbarQR`. При идентификаторе подключения `Zbar`
объект создаётся как `Новый("AddIn.Zbar.ZbarQR")`.

| Английский метод | Русский метод | Результат |
| --- | --- | --- |
| `Version()` | `Версия()` | Строка `0.1.0` |
| `ReadQR(ПутьPNG)` | `ПрочитатьQR(ПутьPNG)` | Первый найденный QR, либо пустая строка |
| `ReadQRs(ПутьPNG)` | `ПрочитатьВсеQR(ПутьPNG)` | JSON-массив всех QR, либо `[]` |

Порядок нескольких кодов не гарантируется. Методы вызываются как функции.
Путь — непустая строка UTF-16. Результат ZBar преобразуется из UTF-8 в UTF-16;
двоичные QR с некорректным UTF-8 этими строковыми методами не поддерживаются.
Ошибки передаются через `AddError`, вызов возвращает `false`. Возвращаемые
строки выделяются через менеджер памяти 1С. Свойств и значений параметров по
умолчанию нет. Допустимы изолированное и неизолированное подключение.

Поддерживаются RGB, grayscale, палитровый PNG и прозрачность (на белом фоне).
Ограничения: 64 МиБ входного файла и 32 мегапикселя. Другие штрихкоды,
камеры и пользовательский интерфейс ZBar не собираются.

## Проверки и ограничения

`qr_reader`: 10 случаев — обычный, палитровый, прозрачный и повёрнутый PNG,
несколько QR, отсутствие QR, кириллица, отсутствующий, повреждённый и усечённый
файлы. `native_api`: динамическая загрузка библиотеки, экспорт, создание/удаление
объекта, метаданные, память и отказ выделения, Unicode в пути/данных, JSON и ошибки.

[Windows x86/x64 workflow](https://github.com/yurbekzhan/ZbarAdd1C/actions/workflows/windows.yml)
собирает MSVC Release для обеих архитектур, запускает оба набора тестов
отдельно для x86 и x64, проверяет зависимости обеих DLL
и сохраняет ZIP как артефакт. Прохождение тестового хоста не заменяет проверку
загрузки в реальной платформе 1С. Такая проверка ещё не выполнена.

Заголовки Native API взяты без изменения из предоставленного примера
`1CGetImageFragment`; их происхождение — `third_party/1c/README.md`.
Пример старый, с интерфейсом локализации `SetLocale`; для конкретной версии 1С
рекомендуется сверка с её SDK. Веб-клиент и мобильная платформа не проверялись.

## Проверка ядра на Linux

```sh
sudo apt-get install build-essential cmake uuid-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 2
ctest --test-dir build --output-on-failure
```

Зависимости изображений здесь тоже собираются из включённых исходников; Windows ZIP
создаётся только на Windows. Для системных ZBar/libpng можно явно указать
`-DZBAR1C_BUNDLED_DEPS=OFF` и установить их development-пакеты.

Python нужен только для пересоздания уже сохранённых PNG-фикстур:

```sh
python -m pip install -r tests/requirements.txt
python tests/generate_fixtures.py
```
